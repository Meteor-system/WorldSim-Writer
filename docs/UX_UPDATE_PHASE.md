# WorldSim-Writer 用户体验更新阶段路线图

## 背景

真实用户体验评估指出：当前产品已经具备强审批、世界状态推进和事件记录能力，但用户第一分钟还不够有吸引力，也不容易理解“批准章节”为什么重要。下一阶段要把 WorldSim-Writer 从“创作后台”升级成“每天想打开的故事世界运营体验”。

## 阶段目标

1. **3 分钟闭环**：新用户能快速完成“选择世界胚胎 → 生成第一章 → 查看世界变化 → 写入正史”的最小成就体验。
2. **解释审批价值**：把批准章节解释为“写入 canon / 正史”，明确世界进度推进、角色变化、悬念/伏笔变化会影响后续章节。
3. **游戏化世界反馈**：批准后立即展示结算反馈，让用户看到世界从 v1 推进到 v2，以及本章实际改变了什么。
4. **用户化术语**：逐步替换或解释工程术语，让作者理解而不是学习后台字段。
5. **情绪化等待体验**：LLM 生成等待不只是“loading”，而是创作流程中的有情绪反馈阶段。
6. **故事世界运营感**：首页、创作台、审批台都应帮助用户感到自己在运营一个活故事世界。

## 术语用户化映射

| 工程术语 | 用户侧表达 | 用法 |
| --- | --- | --- |
| world version | 世界进度 | 展示为“世界进度 v1 → v2” |
| approval | 写入正史 | 按钮和结算页使用“写入正史”解释 |
| consistency | 设定冲突检查 | 用于审批前风险说明 |
| projection changes | 本章带来的世界变化 | 展示角色/悬念/伏笔变化 |
| foreshadow | 悬念/伏笔 | 列表和结算统一使用 |
| event log | 世界历史记录 | 解释为“已写入世界历史记录” |
| canon | 正史 / canon | 两者并用，帮助用户建立产品概念 |

## 优先级

### P0：审批后世界推进结算页 / 反馈区

**目标**：用户批准章节后，立即看到“世界已经向前推进”的结果，而不是只回到概览页。

**首轮验收标准**：

- 批准章节后展示一个结算反馈区。
- 反馈区展示世界进度变化，例如 `世界进度 v1 → v2`。
- 展示批准章节数变化或当前已写入正史章节数。
- 展示本章带来的角色变化数。
- 展示本章带来的悬念/伏笔变化数。
- 展示世界历史记录存在，例如“已写入世界历史记录”。
- 明确说明下一章将基于这些变化继续生成。
- 提供下一步 CTA：继续下一章、查看世界概览、导出世界档案。
- 优先使用现有 API 数据；只有缺数据才补后端。

### P1：新手 3 分钟闭环

**目标**：新用户第一分钟被抓住，三分钟内看到可读章节和可见世界变化。

**验收标准**：

- 新用户入口优先呈现高张力世界胚胎，而不是后台表单。
- 引导步骤清晰：选世界胚胎 → 生成第一章 → 写入正史 → 查看世界变化。
- 完成第一章后给出明确成就反馈和下一步。

### P2：世界状态仪表盘

**目标**：把世界概览从资料陈列升级为“今天这个世界需要处理什么”。

**验收标准**：

- 展示故事世界当前状态、活跃角色、紧迫悬念/伏笔、近期历史。
- 给出推荐行动，例如继续下一章、修复设定冲突、回收伏笔。
- 与审批结算页共享“世界运营”语言。

### P3：全局术语和等待体验优化

**目标**：减少后台感，强化故事运营情绪。

**验收标准**：

- 关键按钮、面板和提示逐步替换为用户化术语。
- LLM 等待状态展示创作阶段提示，例如“导演正在拆场景”“设定冲突检查中”“正在整理本章写入正史后的影响”。

## 第一轮实现范围

本轮只实现 P0 的最小可交付版本：审批后世界推进结算反馈区。若现有接口已经返回足够数据，前端整合优先，不扩展后端。后续再迭代成完整结算页、新手闭环和世界仪表盘。
