# WorldSim-Writer 用户体验更新阶段路线图

## 背景

真实用户体验评估指出：当前产品已经具备强审批、世界状态推进和事件记录能力，但用户第一分钟还不够有吸引力，也不容易理解“批准章节”为什么重要。下一阶段要把 WorldSim-Writer 从“创作后台”升级成“每天想打开的故事世界运营体验”。

## 阶段目标

1. **3 分钟闭环**：新用户能快速完成“选择世界胚胎 → 生成第一章 → 查看世界变化 → 写入正史”的最小成就体验。
2. **解释审批价值**：把批准章节解释为“写入 canon / 正史”，明确世界进度推进、角色变化、悬念/伏笔变化会影响后续章节。
3. **游戏化世界反馈**：批准后立即展示结算反馈，让用户看到世界从 v1 推进到 v2，以及本章实际改变了什么。
4. **用户化术语**：逐步替换或解释工程术语，让作者理解而不是学习后台字段。
5. **情绪化等待体验**：LLM 生成等待不只是“loading”，而是创作流程中的有情绪反馈阶段。
6. **故事世界运营感**：首页、创作台、审批台都应帮助用户感到自己在运营一个活故事世界。

## 术语用户化映射

| 工程术语 | 用户侧表达 | 用法 |
| --- | --- | --- |
| world version | 世界进度 | 展示为“世界进度 v1 → v2” |
| approval | 写入正史 | 按钮和结算页使用“写入正史”解释 |
| consistency | 设定冲突检查 | 用于审批前风险说明 |
| projection changes | 本章带来的世界变化 | 展示角色/悬念/伏笔变化 |
| foreshadow | 悬念/伏笔 | 列表和结算统一使用 |
| event log | 世界历史记录 | 解释为“已写入世界历史记录” |
| canon | 正史 / canon | 两者并用，帮助用户建立产品概念 |

## 优先级

### P0：审批后世界推进结算页 / 反馈区

**目标**：用户批准章节后，立即看到“世界已经向前推进”的结果，而不是只回到概览页。

**首轮验收标准**：

- 批准章节后展示一个结算反馈区。
- 反馈区展示世界进度变化，例如 `世界进度 v1 → v2`。
- 展示批准章节数变化或当前已写入正史章节数。
- 展示本章带来的角色变化数。
- 展示本章带来的悬念/伏笔变化数。
- 展示世界历史记录存在，例如“已写入世界历史记录”。
- 明确说明下一章将基于这些变化继续生成。
- 提供下一步 CTA：继续下一章、查看世界概览、导出世界档案。
- 优先使用现有 API 数据；只有缺数据才补后端。

### P1：新手 3 分钟闭环

**目标**：新用户第一分钟被抓住，三分钟内看到可读章节和可见世界变化。

**验收标准**：

- 新用户入口优先呈现高张力世界胚胎，而不是后台表单。
- 引导步骤清晰：选世界胚胎 → 生成第一章 → 写入正史 → 查看世界变化。
- 完成第一章后给出明确成就反馈和下一步。

### P2：世界状态仪表盘

**目标**：把世界概览从资料陈列升级为“今天这个世界需要处理什么”。

**验收标准**：

- 展示故事世界当前状态、活跃角色、紧迫悬念/伏笔、近期历史。
- 给出推荐行动，例如继续下一章、修复设定冲突、回收伏笔。
- 与审批结算页共享“世界运营”语言。

### P3：全局术语和等待体验优化

**目标**：减少后台感，强化故事运营情绪。

**验收标准**：

- 关键按钮、面板和提示逐步替换为用户化术语。
- LLM 等待状态展示创作阶段提示，例如“导演正在拆场景”“设定冲突检查中”“正在整理本章写入正史后的影响”。

### Route A / P-next：一句话开书 MVP

**目标**：把新手冷启动从“先理解并填写完整世界创建表单”降低为“说出一个故事脑洞”。用户只需要输入一句话，系统生成可审阅的世界创建草稿，并把用户带入第一章 Studio 审稿。

**推荐 MVP 流程**：

1. 用户输入一句故事想法，例如“一个所有人出生时都会被分配未来死因的王国”。
2. 系统生成“世界创建草稿”，自动填满现有创建世界表单和 Seed/Preset 字段，包括标题、题材、基调、核心设定、主角、初始冲突和第一章目标。
3. 用户在表单中确认或修改，确认前不创建正式世界。
4. 用户确认后创建世界，进入现有世界概览与 3 分钟闭环。
5. 系统基于该世界草稿自动生成第一章草稿，进入 Studio 审稿。
6. 用户在 Studio 中审阅正文和拟议世界变化，点击“写入正史”后才推进世界进度、事件历史和 canon 状态。

**验收重点**：

- 用户无需理解完整高级表单，也能从一句话进入可运营世界胚胎。
- 自动填表结果必须可见、可编辑、可确认。
- 第一章草稿必须进入 Studio 审稿，而不是直接写入正史。
- 世界进度、EventLog、canon 守护和章节 approval 仍是唯一正式生效边界。

**后续增强方向**：

- 支持多版本世界草稿，让用户在 2-3 个不同题材/基调方向中选择。
- 支持从一句话继续追问 1-3 个关键问题，而不是一次性暴露完整高级表单。
- 支持与导入节点联动：一句脑洞可以引用候选素材，但候选素材仍只作为写作参考，不能自动变成正式 canon。
- 支持为不同 Seed/Preset 生成首章目标、主角关系、伏笔压力和故事健康初始提示。

### Route B：参考文本提炼与风格手册 MVP

**目标**：用户导入或粘贴参考文本后，系统提炼可产品化的“风格手册”或“参考作品结构手册”，用于指导原创世界和章节，而不是承诺复制某位作者的文笔。

**推荐 MVP 流程**：

1. 用户导入或粘贴参考文本，并标明来源类型：自有作品、授权文本、公版/公共领域文本，或仅作一般阅读参考的文本。
2. 系统提炼风格手册，覆盖叙事节奏、语言密度、对白比例、场景推进、悬念结构、人物关系张力、伏笔埋设/回收方式等抽象维度。
3. 用户确认风格手册内容；确认前不写入正式世界设定。
4. 风格手册作为 Seed/Preset 的辅助输入，用于“一句话开书”生成原创世界草稿，或用于下一章 Studio 草稿生成的写作参考。
5. 章节草稿仍进入 Studio 审稿；只有用户确认的正文和勾选的世界变化才写入正史。

**验收重点**：

- 参考文本先进入 Import Node / 候选素材 / 风格手册草稿，不直接污染 canon。
- 风格手册输出的是抽象结构和风格参数，不复用原文句子、人物名、专有设定或标志性桥段。
- Studio 能解释“本章使用了哪些写作参考”，并继续区分写作参考与拟写入世界变化。

**后续增强方向**：

- 对用户自有作品、授权文本、公版/公共领域文本提供更深的风格适配，例如句式节奏、章节结构、场景密度和对白习惯的可调参数。
- 支持多个风格手册混合，但必须展示每个手册贡献的是抽象参数，而不是复制原文内容。
- 支持将风格手册绑定到世界 Seed/Preset、角色台词策略、章节节奏模板和文学性二审指标。

### Route C：两者合流，风格手册 + 一句话开书 + 第一章草稿

**目标**：形成更完整的新手入口：用户先提供参考文本建立写作方向，再用一句话生成原创世界和第一章草稿，最终进入 Studio 审稿。

**推荐 MVP 流程**：

1. 参考文本 -> 风格手册草稿。
2. 用户确认风格手册。
3. 一句话开书 -> 原创世界创建草稿。
4. 系统把风格手册作为 Seed/Preset 辅助输入，自动填满创建世界表单。
5. 用户确认创建世界。
6. 系统生成第一章草稿，进入 Studio 审稿。
7. 用户逐章写入正史，世界进度和 EventLog 按 approval 推进。

**验收重点**：

- 用户能看懂哪些内容来自参考文本风格手册，哪些来自一句话世界草稿。
- 候选素材和风格手册只影响写作参考，不自动写入正式 canon。
- 第一章依旧是草稿，必须经过 Studio 审稿和写入正史确认。

### 后续：自动连载 / 多章生成，但逐章写入正史确认

**方向说明**：当 Route A-C 稳定后，可以探索“自动连载”或“多章连续生成”。但该能力不能退化成一次性无审稿生成整本小说，应继续体现 WorldSim 的差异化：canon 守护、世界进度、逐章确认、伏笔收束和事件历史可追溯。

**建议边界**：

- 多章生成可以提前规划，但每章都必须有独立草稿、审稿、拟议世界变化和写入正史确认。
- 世界进度只能在每章 approval 后递增，不能因为多章草稿已生成就提前推进。
- EventLog 只记录正式写入的章节事件，不记录未确认草稿为正式历史。
- 自动连载必须配合叙事收束能力，避免只扩张新线索、不回收伏笔。

### 版权与风格安全边界

- 一句话开书应生成原创世界胚胎，不应鼓励用户输入“照着某本未授权作品重做一个世界”。
- 如果用户输入明显指向受保护作品的角色名、专有设定或标志性桥段，系统应抽象为通用题材参数和冲突类型，避免复用原文表达、角色名、专有名词和高度相似桥段。
- 对在世作者或未授权作品，不提供“完全模仿某某作者文笔”的产品话术。
- 对用户自有作品、授权文本、公版/公共领域文本，可允许更深入的风格适配，但仍应保留来源记录和用户确认。
- 风格手册是写作参考，不是 canon；不得自动修改世界事实、角色状态、世界进度或事件历史。
- 第一版不建议无确认地直接生成整本小说；应保留“世界创建草稿 -> 用户确认 -> 章节草稿 -> Studio 审稿 -> 写入正史”的可审计链路。
