# Chapter Intent Context Version Contract Design

## Goal

Prevent stale next-chapter execution contexts from being frozen into new chapter sessions or direct drafts.

## Problem

The chapter intent contract now allows clients to pass a structured `execution_context` with `source_world_version`. The backend stores this context and injects it into Outliner/Writer prompts, but `normalize_execution_context()` currently only overwrites the goal and does not verify that the context was prepared against the current `World.world_version`.

That leaves a subtle main-flow risk: a user can open Studio with a prep context from an older world version, create a new chapter after the world changes, and the draft still receives stale priority characters, foreshadows, recent events, and continuity warnings. Approval version checks use `ChapterDraft.source_world_version`, not `execution_context.source_world_version`, so the stale intent can pass approval readiness as long as the draft itself was generated at the latest world version.

## Brainstormed Options

1. Silently rewrite `execution_context.source_world_version` to the current world version. This avoids errors, but loses the audit value of the frozen context and can make stale prep look current.
2. Allow stale context but downgrade approval readiness. This catches the issue late, after a model call and draft creation.
3. Reject stale provided execution context before creating a chapter or draft. This preserves the contract: execution context is a frozen intent snapshot and must match the world version it claims to describe.

## Selected Design

Use option 3. `normalize_execution_context()` should reject any provided context whose `source_world_version` differs from the current world version with HTTP `409 WORLD_VERSION_MISMATCH`.

Manual contexts generated by the backend already use the current world version and remain unchanged. Provided contexts from Next Chapter Prep must be refreshed before use if the world advanced.

## Scope Boundaries

- Do not change approval transaction semantics.
- Do not rewrite or silently patch stale execution contexts.
- Do not add frontend UI in this slice.
- Do not repeat completed smoke diagnostics work.

## Test Strategy

- Add a failing API regression for `POST /worlds/{world_id}/chapters` with a stale `execution_context.source_world_version`.
- Add a failing API regression for `POST /worlds/{world_id}/chapters/draft` with a stale execution context, using a capturing fake LLM to prove no model call occurs.
- Update existing execution-context tests so valid provided contexts use the current world version.
- Implement the minimal version check in `normalize_execution_context()`.
